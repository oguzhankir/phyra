# Phyra contributor guide for agents

Phyra is an AI-native engineering analysis desktop workbench combining classical FEM and experimental Physics ML for 3D solid and 2D plane-stress elasticity. The fixed product stack is Tauri 2, React, and TypeScript. Future thermal, fluid, multiphysics, and Physics ML work must preserve project/study/execution/field boundaries without adding placeholder modules.

Implementation ownership: `src/App.tsx` orchestrates project, file and job lifecycle; `src/features/workbench/` owns navigation, property controls and themes; `src/features/viewport/` owns Three.js rendering and scientific transfer functions; `src/features/runs/` owns execution/training/comparison views; `src/features/help/` owns offline contextual engineering guides. Shared authoritative fields, generated contracts and the native bridge remain at `src/`. `src-tauri/` owns native files, isolated engine jobs, cancellation, and packaging; `engine/phyra_engine/` contains headless Gmsh meshing, SciPy sparse mechanics, and real PyTorch elasticity PINNs; `engine/tests/` contains independent numerical references. `contracts/project.schema.json` is the canonical project schema; `examples/` holds editable SI projects; `public/reference/` holds small validated CPU results for browser inspection, generated by `scripts/generate-reference.mjs`; `scripts/` owns setup, worker bundling, real-capture media composition and workflow verification. Gmsh provides curved and connected primitive domains and a future solid-import route. An owned out-of-process Python worker isolates numerical faults and cancellation. Bulk arrays use binary buffers rather than reactive JSON vertex lists.

Internal coordinates, loads, material properties, transported fields and FEM use SI and float64. PINN training uses float64 on CPU/CUDA and float32 on probed MPS; preserve its actual device/precision metadata. Rendering conversions must not alter authoritative data. Region identifiers describe geometry boundaries and persist through remeshing. Geometry edits invalidate incompatible assignments. Results identify project, study, input fingerprint, mesh, and job. Editing inputs makes old results stale; late or cancelled jobs cannot publish current results.

Commands are canonical in `package.json`; exact prerequisites and local sequences live in CONTRIBUTING.md. Use `npm ci`, `npm run setup`, `npm run package:engine`, and `npm run dev` for desktop development; `npm run check`, `npm test`, `npm run test:native`, `npm run check:native`, and `npm run test:numerics-slow` for verification; `npm run package` and `npm run test:desktop` for packaging and actual workflow checks. Keep Rust and dependency lockfiles pinned. Prefer official Python 3.12 on macOS; packaging inspects every native binary against the declared macOS 14 minimum and rejects developer-library dependencies.

Numerical changes require independent analytical/manufactured references, conservation, mesh convergence where relevant, and failure tests. PINNs require actual autograd PDE/boundary residuals, measured losses and same-location FEM comparison; never substitute FEM labels or claim that training loss proves accuracy. Keep headless tests independent of desktop imports. Never invent properties, outcomes, screenshots, reference values, or benchmarks; loosen no tolerance to hide a defect. Never silence unexplained numerical warnings, add hidden stabilization/constraints, publish stale results, or change persistence without explicit version handling.

Keep README.md, AGENTS.md, CONTRIBUTING.md, LICENSE and the explicitly requested roadmap.md as canonical human documentation. Roadmap is the single planning document; product help is versioned beside its implemented capabilities. Legal notices, license texts, small community templates, test fixtures, real product media and colocated mathematical comments have concrete purposes. Do not add duplicate plans, progress logs, reports, architecture documents, duplicate instructions, a docs tree, unused dependencies, speculative interfaces, or prohibited competitor names. Default to neutral light UI with a restrained charcoal dark alternative; keep numerical data, contour mappings and rendering presentation separate.

Preserve unknown working-tree changes. Never reset, clean, stash, or publish without authorization. Use configured identity and DCO sign-off for any commits; do not invent author details. Preserve GPL-3.0-or-later and required upstream notices; Gmsh/native redistribution requires complete Corresponding Source and a target-specific dependency audit. Windows x64 and macOS Apple Silicon are primary targets; distinguish configuration, build, package inspection, launch, solve and clean-machine evidence. Do not claim signing, CI success or platform verification without it.

Only application-selected executable paths are permitted. No public service, general shell bridge, accounts, telemetry, paid compute, or cloud solver. Validate untrusted projects, arrays, dimensions, indices, finite values, and cumulative resource limits before use. Definition of done: editable 2D/3D geometry-to-results loops, real cancellable PINN training/comparison, verified mechanics, safe persistence, owned-worker cleanup, tested available-target package, concise honest platform limitations.
