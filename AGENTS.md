# Phyra contributor guide for agents

Phyra is an AI-native engineering analysis desktop workbench combining classical FEM and experimental Physics ML for 3D solid and 2D plane-stress elasticity. The fixed product stack is Tauri 2, React, and TypeScript. Future thermal, fluid, multiphysics, and Physics ML work must preserve project/study/execution/field boundaries without adding placeholder modules.

Frontend ownership: `src/app/` composes lifecycle and project transitions. `useProjectSession` owns definitions, numeric drafts, bounded edit history and archive association; `useCadSession` owns CAD request leases and preview publication; `useExecutionSession` and `ExecutionOwnership` own worker leases and result publication; `useWorkbenchView` owns presentation; feature editors consume narrow contracts rather than the composition hook. CAD command drafts remain transient until Apply; preview jobs are discarded before display publication and never establish analysis/export eligibility. Keep numeric draft reporters stable, do not dirty a saved document before Apply, and block clean-document replacement while a command is unresolved. `src/domain/` owns scientific contracts, project/history rules, units and fields; `src/platform/desktop/` owns the typed native bridge; `src/shared/` owns reusable forms and modal behavior. `src/features/` contains workbench navigation, project editors, diagnostics, viewport, run views, examples and offline help. `src-tauri/src/application.rs` wires native startup; `cad/` owns isolated exact geometry jobs and export; `execution/` owns numerical workers, cancellation and job state; `project/` owns archives, validation and recovery; `results/` owns field/export checks; `platform/` owns native file access; `verification/` and `tests/` own real workflow evidence.

Python ownership: `geometry/`, `meshing/` and `materials/` own geometric/discretization/constitutive kernels; `physics/elasticity/` owns method-independent loads, restraints and analytical fields. `studies/` validates canonical definitions and prepares meshes. `methods/classical/` and `methods/physicsml/` own algorithms; PINN configuration, normalization, sampling, residuals, potential-energy quadrature/exact finite-segment lifting, optimization, held-out validation and field evaluation have separate modules. `protocol/` decodes bounded requests into immutable validated snapshots; `execution/application.py` plans and executes studies independently of CLI framing; `execution/worker.py` only adapts stdio/errors; `results/` owns field diagnostics, validated caches and publication. Use pure functions for numerical kernels and named immutable records for configuration/measurements; keep stateful optimization and execution ownership explicit. `engine/tests/` holds independent references and boundary/lifecycle regressions. `npm run check` enforces frontend and Python dependency ownership, including deferred imports. Add modules for real responsibilities, not anticipated capabilities; new methods reuse physical definitions and must not mutate execution inputs.

`contracts/project.schema.json` is canonical version 7; frozen v1/v2/v3/v4/v5/v6 schemas validate old definitions before migration. Version 1 caches are discarded; v2/v3 and unchanged v4 primitive-study caches pass normal worker ownership, fingerprint and field validation before reuse. Legacy versions migrate to strong-form; its unchanged physical digest preserves validated v4 caches. Potential-energy configuration has a distinct digest. Profile and traction inputs have a distinct physical fingerprint. `examples/` holds editable SI projects; `public/reference/` holds bounded validated CPU results generated by `scripts/generate-reference.mjs`; `scripts/` owns setup, bundling and workflow verification. OpenCASCADE owns exact CAD recipes, STEP interchange and display tessellation in isolated CAD workers; SolveSpace libslvs owns bounded sketch constraints. Loft/sweep solids or surface shells and independent assembly components remain definition-only for analysis. Component paths identify instances; coincident instances never imply bonds or contact. CAD display triangles are never a numerical mesh. Transient single-solid CAD mesh inspection generates independent Gmsh tetra4 elements with mesh-scoped boundaries; it cannot establish analysis support, persistent assignments, exact export ownership or archive/cache state. Discard inspection jobs before display publication and invalidate previews on geometry edits. Exact supported CAD adapters derive solver geometry without replacing the authored recipe or its fingerprint. Gmsh provides curved and connected supported numerical domains; general solid-import analysis remains gated. An owned out-of-process Python worker isolates numerical faults and cancellation. Bulk arrays use binary buffers rather than reactive JSON vertex lists.

Internal coordinates, loads, material properties, transported fields and FEM use SI and float64. PINN training uses float64 on CPU/CUDA and float32 on probed MPS; preserve its actual device/precision metadata. Rendering conversions must not alter authoritative data. Region identifiers describe geometry boundaries and persist through remeshing. Geometry edits invalidate incompatible assignments. Results identify project, study, input fingerprint, mesh, and job. Editing inputs makes old results stale; late or cancelled jobs cannot publish current results.

Session undo/redo holds definitions only, bounded to 80 transactions and 16 MiB; preserve project/study identity and advance the current revision on physical undo/redo. New/open/reference/restore resets history. CAD gestures and numeric edits commit as completed transactions; open-sketch solving preserves graph identities/relationships and does not fabricate an exact-shape receipt. Presentation outlines and stale previews never enable topology assignments, export or analysis. Named boundary sets are copied preparation metadata, bounded to 100, stamped with primitive/dimension and explicitly repaired after incompatible edits; they are not associative CAD links. Viewport selection, isolation and camera state never alter fields; measurement uses undeformed mesh-node/preview-vertex SI coordinates.

Recovery journals hold validated project definitions only; imported immutable STEP definition sources live in a bounded native content-addressed store and travel inside .phyra archives, with native-owned paths, isolated sessions and ordered writes. Each open document owns definitions/history, file association, recovery, worker leases and result publication; focusing another tab does not transfer ownership. Read/discovery migrates older validated journals in memory without rewriting their bytes. Invalid drafts pause checkpoints. Restoring opens an unsaved definition without original file association, cached fields or weights; failed restore/discard must preserve recoverable copies. Do not confuse recovery with scientific result persistence or trained-model resume.

Optional AI assistance uses explicit user-approved provider connections and the same versioned offline help. `src/features/assistant/` owns context/presentation, `src/app/useAssistantSession.ts` is a thin document-identity adapter; `src/features/assistant/session/` owns conversation/stream lifecycle, injected request transactions and scoped MCP publication, `src/platform/desktop/assistant.ts` owns the typed bridge, and `src-tauri/src/assistant/` owns native provider transport, OS credentials, bounded local history and scoped stdio MCP. Initialize assistant storage on panel use and keep OS credential/storage waits off native UI threads. Keys stay in native OS storage, namespaced by provider and endpoint origin; they are never returned to frontend state. Persist exact supplied context and provider/model/endpoint provenance separately from .phyra archives. CAD-only project context may include bounded current exact-evaluation and open-sketch constraint evidence; it stays separate from numerical results and is available to MCP only under project permission. No automatic files or bulk field buffers are attached. A deliberate Send authorizes the selected connected provider to receive the bounded current context and history; do not add recurring attachment/approval dialogs. Preserve original snapshot identity, cancellation, publication ordering and native tool revocation; assistant claims never establish physical correctness. Provider connections are independent and stored in validated version 2 settings with explicit version 1 migration. The current MCP surface is read only, uses individually enforced tool allowlists and is pinned to protocol 2025-11-25; future mutations require explicit typed validation and authorization.

Commands are canonical in `package.json`; exact prerequisites and local sequences live in CONTRIBUTING.md. Use `npm ci`, `npm run setup`, `npm run package:engine`, and `npm run dev` for desktop development; `npm run check`, `npm test`, `npm run test:native`, `npm run check:native`, and `npm run test:numerics-slow` for verification; `npm run package` and `npm run test:desktop` for packaging and actual workflow checks. Keep Rust and dependency lockfiles pinned. Prefer official Python 3.12 on macOS; packaging inspects every native binary against the declared macOS 14 minimum and rejects developer-library dependencies.

Numerical changes require independent analytical/manufactured references, conservation, mesh convergence where relevant, and failure tests. PINNs require actual autograd PDE/boundary residuals, measured losses and same-location FEM comparison; never substitute FEM labels or claim that training loss proves accuracy. Keep headless tests independent of desktop imports. Never invent properties, outcomes, screenshots, reference values, or benchmarks; loosen no tolerance to hide a defect. Never silence unexplained numerical warnings, add hidden stabilization/constraints, publish stale results, or change persistence without explicit version handling.

Keep README.md, AGENTS.md, CONTRIBUTING.md, LICENSE, CHANGELOG.md, the single `ROADMAP.md`, SECURITY.md and CITATION.cff as canonical documentation/metadata. Update CHANGELOG.md under Unreleased for every PR that changes user-visible behavior, scientific outcomes/assumptions, compatibility, persistence, supported platforms or security. For internal, test-only, contributor-tooling or typo changes with no such effect, state `Changelog: N/A — reason` in the PR; follow the policy in CONTRIBUTING.md. Product help is versioned beside its implemented capabilities. Cite primary methods near implementation/tests and in useful product help; never invent release dates, DOI, certified material properties or framework/hardware support. The promotional video and help images show the v0.3.0 interface with genuine saved CPU references. Keep recorded results distinct from live training and roadmap direction distinct from implemented capabilities. Legal notices, license texts, small community templates, test fixtures, real product media and colocated mathematical comments have concrete purposes. Do not add duplicate plans, progress logs, reports, architecture documents, duplicate instructions, a docs tree, unused dependencies, speculative interfaces, or prohibited competitor names. Default to neutral light UI with a restrained charcoal dark alternative; keep numerical data, contour mappings and rendering presentation separate.

Preserve unknown working-tree changes. Never reset, clean, stash, or publish without authorization. Use configured identity and DCO sign-off for any commits; do not invent author details. Phyra's original source code is Apache-2.0; preserve LICENSE, NOTICE and all separately licensed upstream material. Bundled Gmsh and SolveSpace remain GPL-covered, and the combined application must comply with GPLv3 and other applicable upstream terms. Native redistribution still requires complete Corresponding Source and a target-specific dependency audit; the first-party license change does not authorize Apache-only installers or revoke prior GPL grants. Windows x64 and macOS Apple Silicon are primary targets; distinguish configuration, build, package inspection, launch, solve and clean-machine evidence. Do not claim signing, CI success or platform verification without it.

Only application-selected executable paths are permitted. Optional user-approved BYOK AI connections may use the user’s provider account/key or a local loopback endpoint; numerical meshing, FEM and PINN stay local. No Phyra accounts, telemetry, public service, general shell bridge, paid numerical compute or cloud solver. Validate untrusted projects, assistant context/output, arrays, dimensions, indices, finite values, and cumulative resource limits before use. Definition of done: editable 2D/3D geometry-to-results loops, real cancellable PINN training/comparison, verified mechanics, safe persistence, owned-worker cleanup, tested available-target package, concise honest platform limitations.
